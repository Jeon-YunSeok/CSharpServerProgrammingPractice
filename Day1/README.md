# Day1-TCP Echo Server

---

## 1. 개념 설명

### 1-1 서버와 클라이언트

**서버:** 접속한 플레이어들의 정보 관리
**클라이언트:** 서버에 요청을 보내거나 서버가 전달하는 데이터 수신

*멀티플레이어 게임에서는 서버가 플레이어의 이동 가능 여부를 판단하고 계산된 상태를 다른 클라이언트들에게 전달하는 구조를 사용할 수 있다.*

### 1-2 TCP

**TCP(Transmission Control Protocol):** 두 프로그램 사이의 연결을 설정하고, 데이터를 순서대로 안정적으로 전달하도록 설계된 전송 계층 프로토콜

| **특징** | **설명** |
| --- | --- |
| 연결 지향 | 통신 전에 연결 설정 |
| 신뢰성 | 손실된 데이터의 재전송 등 제공 |
| 순서 보장 | 전송된 바이트 순서 유지 |
| 바이트 스트림 | 메시지 경계를 자동으로 구분하지 않음 |

가장 중요한 점은 *TCP가 메시지가 아니라 연속된 바이트 스트림을 전달한다는 것*
예를 들어, "Hello World" 라는 문장을 클라이언트에서 "Hello"와 "World"를 따로 전송하더라도 서버에서 수신할 때 Read()를 한 번 사용할 수도(HelloWorld) 세 번 사용할 수도(Hel/loWo/rld) 있다.

### 1-3 IP 주소와 Port

서버에 접속하려면 IP 주소와 포트 번호가 필요하다.

**IP 주소:** 어떤 컴퓨터 또는 네트워크 인터페이스에 연결할 것인지
**Port:** 해당 컴퓨터의 어떤 네트워크 서비스를 사용할 것인지
**Socket:** 프로그램이 네트워크 통신을 수행하는 엔드포인트

예를 들어, 127.0.0.1:5000이라는 주소가 있을 때 127.0.0.1은 컴퓨터를 가리키는 루프백 주소, 5000은 서버가 사용할 포트 번호를 의미한다.


## 2. 코드

해당 서버의 목적은 다음과 같다.

1. 포트 5000에서 클라이언트 접속 대기
2. 클라이언트가 접속하면 메세지 수신
3. 수신한 메세지를 콘솔에 출력
4. 메세지를 클라이언트에 다시 전송
5. 클라이언트의 연결이 종료되면 다음 연결 대기

ReadLine()을 사용하여 TCP 데이터를 여러 조각으로 수신하더라도 한 줄을 완성할 때까지 기다릴 수 있고, WriteLine()를 사용하여 TCP 메시지를 구분한다.

### 2-1 서버 코드

#### 핵심 클래스 TcpListener

서버 측에서 TCP 연결 요청을 받기 위한 클래스이다.
외부 클라이언트와의 연결을 허용하려면 서버의 바인딩 주소와 방화벽 설정을 별도로 구성해야 한다. 

#### 연결 메서드 AcceptTcpClient()

클라이언트가 연결할 때까지 현재 스레드의 실행을 차단한다. 
게임 서버에서는 수많은 클라이언트들의 동시 접속을 위해 **AcceptTcpClientAsync()**을 사용한다.

#### 데이터 통신 NetworkStream

연결된 클라이언트와 바이트 데이터를 주고받기 위한 스트림을 가져온다. 
게임 패킷을 구현할 때는 **StreamReader**와 **StreamWriter**를 사용하지 않고 바이트 배열을 직접 처리한다.
